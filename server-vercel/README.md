# Push-уведомления через Vercel — с диагностической страницей

Полностью переписанная версия — теперь это настоящий маленький сайт:
открываешь ссылку в браузере и сразу видишь, что настроено, а что нет,
плюс можешь отправить тестовый push прямо со страницы, без консоли и curl.

## Структура

```
server-vercel/
├── index.html        — сама страница (диагностика + тестовая форма)
├── api/
│   ├── notify.js      — POST /api/notify — отправка push (вызывает приложение)
│   └── status.js       — GET /api/status — диагностика (вызывает index.html)
├── lib/
│   └── firebase.js     — общая инициализация Firebase Admin
└── package.json
```

## Деплой

1. **Ключ сервисного аккаунта Firebase** (если ещё нет): Firebase Console
   → шестерёнка → **Project settings** → **Service accounts** →
   **Generate new private key**. Скачается `.json` — храни в секрете.

2. Залей папку `server-vercel/` в GitHub-репозиторий (или весь проект
   целиком — тогда на шаге 3 укажи Root Directory).

3. [vercel.com](https://vercel.com) → **Add New → Project** → выбери
   репозиторий → если заливал весь проект, **Root Directory**:
   `server-vercel` → **Import**.

4. **Settings → Environment Variables**:
   - `FIREBASE_SERVICE_ACCOUNT` — весь JSON сервисного аккаунта одной
     строкой, **вставь его ТОЧНО как он есть в скачанном файле** (это
     самая частая причина поломки — если скопировать текст так, что
     переносы строк внутри `private_key` превратятся в настоящие, JSON
     станет невалидным; страница диагностики теперь прямо укажет на эту
     ошибку, если она есть).
   - `NOTIFY_SECRET` — любая случайная строка, тот же секрет пойдёт в
     `--dart-define=NOTIFY_SECRET=...` при сборке приложения.

5. **Deploy**. Получишь адрес вида `https://твой-проект.vercel.app`.

## Как проверить, что реально работает

1. Открой `https://твой-проект.vercel.app` в браузере (просто открой ссылку,
   ничего больше не нужно).
2. Сразу увидишь три строки с зелёными/красными точками:
   - **Сервер отвечает** — красная точка здесь = деплой не прошёл вообще,
     смотри вкладку Deployments на Vercel.
   - **Firebase Admin подключён** — красная точка = проблема в
     `FIREBASE_SERVICE_ACCOUNT` (страница напишет точную причину текстом
     под точками, читай её — там будет ровно то, что нужно поправить).
   - **NOTIFY_SECRET задан** — красная точка = забыл добавить переменную
     на Vercel.
3. Если все три точки зелёные — заполни форму ниже (два реальных uid из
   Firebase Console → Firestore → users, текст, свой секрет) и нажми
   **Отправить тестовый push**. Внизу появится точный ответ сервера:
   - `{"sent": true}` — всё работает, push реально ушёл;
   - `{"skipped": "no fcm token"}` — получатель ещё ни разу не запускал
     приложение с этим обновлением (нормально, не ошибка);
   - что угодно с `"error"` — текст ошибки прямо укажет на причину.

## Подключение к приложению

```
flutter build apk --release --dart-define=IMGBB_API_KEY=... --dart-define=ADMOB_BANNER_ID=... --dart-define=NOTIFY_SERVER_URL=https://твой-проект.vercel.app --dart-define=NOTIFY_SECRET=тот_же_секрет_что_на_vercel
```

`NOTIFY_SERVER_URL` — только корень домена, БЕЗ `/api/notify` на конце.
Путь приложение добавляет само (см. `lib/services/notify_service.dart`) —
**в предыдущей версии там была ошибка**: код стучался на `/notify` вместо
`/api/notify`, из-за чего все запросы с телефона тихо проваливались с 404,
даже если сам сервер на Vercel был настроен идеально правильно. Теперь
исправлено.
