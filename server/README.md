# Push-уведомления БЕСПЛАТНО, без плана Blaze

Firebase Cloud Functions (папка `functions/`, которую я делал раньше)
требуют платный план Blaze. Это ограничение конкретно Cloud Functions как
продукта, а не самого FCM (Firebase Cloud Messaging) — он бесплатен всегда.
Этот сервер — тот же самый функционал, но развёрнутый на обычном бесплатном
хостинге, без Blaze и без привязки карты. Именно так это устроено и у
Telegram, и у любого другого приложения с push — у них просто есть свой
сервер, который умеет вызывать Apple/Google push-сервисы.

Можно использовать **либо** этот сервер, **либо** `functions/` (если
всё-таки решишь подключить Blaze) — не оба сразу.

## Что нужно

1. **Ключ сервисного аккаунта Firebase** (бесплатно, доступно на любом плане):
   Firebase Console → шестерёнка рядом с "Project Overview" → **Project
   settings** → вкладка **Service accounts** → **Generate new private key**.
   Скачается `.json`-файл — храни его в секрете, никогда не заливай в
   публичный репозиторий.

2. **Аккаунт на [Render.com](https://render.com)** (бесплатно, тот же
   хостинг, что и для твоих других проектов).

## Деплой на Render

1. Залей папку `server/` (или весь проект) в свой GitHub-репозиторий.
2. Render → **New → Web Service** → подключи репозиторий.
3. **Root Directory**: `server` (если заливаешь весь проект целиком).
4. **Build Command**: `npm install`
5. **Start Command**: `npm start`
6. **Environment Variables**:
   - `FIREBASE_SERVICE_ACCOUNT` — содержимое скачанного JSON-файла
     сервисного аккаунта, **вставленное целиком одной строкой** (просто
     скопируй весь JSON и вставь как значение переменной — Render съест
     переносы строк внутри значения нормально).
   - `NOTIFY_SECRET` — придумай любую длинную случайную строку (например,
     сгенерируй на https://www.uuidgenerator.net/) — это пароль, который
     не даст посторонним пользоваться твоим сервером для рассылки чужих
     push-уведомлений.
7. Deploy. После деплоя Render даст тебе URL вида
   `https://kompaniya-push-relay.onrender.com`.

## Подключение к приложению

При сборке передай два новых `--dart-define`, с теми же значениями, что и
на сервере:

```
flutter build apk --release ^
  --dart-define=IMGBB_API_KEY=... ^
  --dart-define=ADMOB_BANNER_ID=... ^
  --dart-define=NOTIFY_SERVER_URL=https://kompaniya-push-relay.onrender.com ^
  --dart-define=NOTIFY_SECRET=тот_же_секрет_что_на_render
```

Если не передать `NOTIFY_SERVER_URL` — приложение просто не будет пытаться
слать push-запросы (см. `lib/services/notify_service.dart`), всё остальное
продолжит работать как обычно.

## Важный нюанс бесплатного плана Render

Бесплатный веб-сервис на Render "засыпает" примерно через 15 минут без
запросов и "просыпается" при следующем запросе за ~30-50 секунд. Это
означает: если твоим приложением давно никто не пользовался, ПЕРВОЕ
уведомление после паузы может прийти с задержкой в полминуты — это
нормально для бесплатного плана, не баг. Если это критично — можно
подключить бесплатный "пингер" (например, cron-job.org раз в 10 минут
дёргает `/`), чтобы сервис не засыпал.

## Проверка, что всё работает

```
curl -X POST https://kompaniya-push-relay.onrender.com/notify \
  -H "Content-Type: application/json" \
  -H "x-notify-secret: тот_же_секрет" \
  -d '{"fromUid":"...", "toUid":"...", "text":"тест"}'
```
Подставь реальные uid двух своих тестовых аккаунтов (посмотреть можно в
Firebase Console → Firestore → users). Ответ `{"sent":true}` — всё
работает. `{"skipped":"no fcm token"}` — получатель ещё ни разу не
запускал приложение с этим обновлением (токен появится сам после первого
запуска).
